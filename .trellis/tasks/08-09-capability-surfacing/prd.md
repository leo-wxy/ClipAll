# 能力外显与插件交互

## Goal

实现类似 PopClip 的系统级取词体验：在支持 macOS Accessibility 的应用中，用户选中文字后可以立即看到一个稳定、克制的原生动作浮层，并从中复制、搜索、翻译或查找其他能力；即使未来能力和插件数量持续增加，浮层也不会无限变宽、频繁换位或迫使用户先理解插件结构。

## Background

- 产品形态是选中文字后贴近选区出现操作浮层的 macOS 工具，未来会通过插件持续增加能力。
- PopClip 是交互基准：保留其“选中文字后自动出现上下文动作”和“扩展提供动作”的核心心智，但不复制其视觉、扩展格式或所有功能。
- 当前仓库尚无产品代码或既有视觉体系，本任务需要建立基础工程和首个纵向可用版本。

## Product Principles

- **能力优先于插件**：主界面展示能力名称和结果，插件归属只作为次级信息。
- **稳定优先于聪明**：固定入口形成肌肉记忆，推荐只提供上下文补充。
- **渐进披露**：默认只显示少量高频能力，完整集合通过搜索和独立管理窗口访问。
- **空间有上限，能力无上限**：能力数量增长不得改变浮层最大宽度和核心层级。
- **用户确认后执行**：内容匹配只能推荐，不能自动运行能力或把选中文字发送到外部服务。
- **动作与结果统一**：简单能力可立即完成，复杂能力在同一浮层展示结果和后续操作。
- **外置插件默认不可信**：导入、校验、执行、调试和卸载都必须经过宿主边界，插件不能直接获得文件、网络、剪贴板或辅助功能权限。

## In Scope

### R1. Selection Capture And Base Action

- 用户用指针完成文字选择后，应用尝试读取当前选中文字和选区位置，并在选区附近显示浮层。
- 用户仅使用键盘选择文字时，可以通过全局快捷键调用同一套浮层和能力。
- 菜单栏提供明确的启用/停用开关；停用时停止自动取词和弹出，但能力中心与设置仍可访问。
- 浮层应优先出现在选区下方；空间不足时切换到上方，并限制在当前屏幕可见区域内。
- `复制` 始终位于首位，将本次捕获的文字写入系统剪贴板后给出成功反馈。
- 未授予辅助功能权限、没有有效选区或目标应用不提供所需信息时，应用不得崩溃或执行旧内容；应显示明确引导或安静退出。

### R2. Stable Fixed Capabilities

- 顶行在 `复制` 之后显示最多 4 个由用户固定和排序的能力。
- 首次安装只显示 `搜索` 与 `翻译`，不显示两个空槽。
- 推荐结果、最近使用记录和内容变化都不能重排固定能力。
- 常见能力保留图标和文字标签，并具有可用、悬停、选中、加载、成功、失败和无权限反馈。

### R3. Capability Model And Content Routing

- 一个插件可以声明一个或多个能力；每个能力独立参与匹配、排序、固定和执行。
- 每个插件可以选择性声明配置项；配置的名称、说明、类型、默认值和可选项由插件拥有，主应用负责统一渲染与持久化。
- 每个能力至少声明稳定标识、名称、图标、用途描述、适用内容类型、典型示例、不适用场景、执行形态和所属插件。
- 内容路由器根据选中文字的语言和内容特征，对能力声明进行本地匹配并输出有理由、可复现的排序结果。
- 最佳且未固定的候选项进入 1 个推荐位；已在顶行外显的固定能力不在推荐行重复展示。
- 推荐行展示能力名称、所属插件、简短匹配原因和明确执行入口。
- 没有达到可信阈值的候选项时，推荐行整体隐藏，不保留空白占位。
- 推荐能力只有在用户点击或键盘确认后才执行；其余匹配项进入“更多能力”的优先结果。

### R4. Bounded Capability Discovery

- 浮层始终提供稳定的“更多能力”入口，并支持直接使用键盘呼出。
- “更多能力”采用固定最大高度的纵向命令面板，不使用无限横向滚动。
- 空查询状态最多显示 5 个内容匹配项和 3 个最近使用项，不显示无限增长的“全部能力”分组。
- 完整能力集合只参与搜索；用户输入名称、描述或插件名称后可以找到任意已注册能力。
- 能力不可用时应在结果中说明原因，例如输入类型不支持、权限未授予或提供方不可用。

### R5. Capability Center

- 用户可以从浮层底部入口和菜单栏打开独立的原生 macOS 能力中心。
- 能力中心负责完整搜索浏览、固定与取消固定、拖动排序、能力描述与示例、所属插件、权限和可用状态。
- 能力中心根据插件声明显示配置区；没有配置声明的插件不显示空配置页。
- 固定能力最多 4 项，修改后立即反映到后续浮层中。
- 关闭或切换能力中心不得修改当前捕获的文字，也不得让浮层执行错误上下文中的能力。
- 应用提供标准 macOS 设置窗口，分为“通用、能力、插件、开发者”四个分区；能力中心负责发现和理解能力，设置窗口负责长期偏好与插件生命周期，避免同一操作在两处出现不同语义。
- 通用设置包含自动取词启停、全局快捷键和辅助功能权限状态；能力设置包含固定项与顺序；插件设置包含导入、启停、卸载和 schema 驱动配置；开发者设置包含开发者模式、开发引用、重载和调试入口。

### R6. Built-in Search And Translation

- `搜索` 是立即动作能力：用户确认后，使用当前配置的搜索提供方在默认浏览器打开选中文字对应的查询。
- `翻译` 是结果面板能力：用户确认后，在浮层内显示系统 Translation framework 的译文。
- 搜索插件提供 Google、Bing 与 DuckDuckGo 搜索引擎切换；翻译插件提供目标语言和翻译提供方切换。配置变更只影响所属插件，不改变其他插件状态。
- 翻译默认使用 Apple 系统翻译；同时提供可配置 endpoint、model 和 API key 的 OpenAI-compatible AI 翻译适配器。未来其他平台通过相同 provider 边界接入。
- AI 翻译的 API key 必须存入系统 Keychain，不得写入 `UserDefaults`、日志或界面明文持久化。
- 翻译应显示模型准备、下载、加载、成功、失败和语言不可用状态。
- 选中文字在执行搜索前不得离开应用；系统翻译在设备端处理。

### R7. External Timestamp Plugin Example

- 首版提供一个独立的 `TimestampTools.clipallplugin` 示例包，用于验证插件声明、同插件多能力、配置、导入、调试、内容推荐、执行和卸载的完整链路；其实现不得编译进主 App target。
- 示例包在仓库中拥有独立目录，并可作为应用资源随分发包提供，但只有通过与普通外置插件相同的安装器后才进入活动注册表。
- 插件提供两个独立能力：`时间戳 → 日期` 与 `日期 → 时间戳`；两者拥有独立描述、示例、排除条件和匹配分数。
- `时间戳 → 日期` 支持明确的 10 位秒级和 13 位毫秒级 Unix 时间戳，结果显示本地时间与 UTC 表达。
- `日期 → 时间戳` 支持 ISO 8601 和首版声明的常见日期时间格式，结果同时显示秒级与毫秒级 Unix 时间戳。
- 日期文本未携带时区时使用当前系统时区，并在结果中明确标注该解释，避免静默产生歧义。
- 时间工具插件允许选择系统时区或 UTC，并允许在标准格式、ISO 8601 和中文日期格式之间切换显示。
- 示例插件不默认占用固定能力位；当内容匹配时，对应具体能力可以出现在推荐行和“更多能力”中。
- 所有解析与转换在本机完成；无法确定输入、数值越界或日期无效时显示可理解错误，不猜测结果。

### R8. External Plugin Lifecycle

- 外置插件采用可检查的 `.clipallplugin` 包目录，至少包含 `plugin.json` 和清单声明的 JavaScript 入口；能力、匹配规则、配置 schema 和执行 handler 都由清单声明。
- 用户可从能力中心导入本地插件包。宿主先在 staging 目录复制并完成 schema、标识、版本、路径、文件数量、体积、符号链接和能力冲突校验，全部通过后才原子安装并注册。
- 未签名的本地插件在安装前明确显示来源、能力、配置字段和运行权限；首版外置运行时只允许无文件、无网络、无剪贴板、无 Accessibility 桥接的本地纯转换。
- 用户可停用、重新启用和卸载外置插件。停用或卸载会立即取消该插件任务、从推荐和能力列表注销其能力，并清理固定/最近引用；卸载默认保留配置，用户可选择同时删除配置和 Keychain 数据。
- 导入源文件永不被修改或删除；普通安装复制到应用支持目录，“加载未打包插件”只在开发者模式保存开发引用，移除时不删除开发者源目录。
- 重复插件 ID 不能静默覆盖。版本替换需要用户明确确认，失败时保留当前已安装版本。
- 插件运行结果必须映射为宿主定义的结构化输出，不能注入自定义 SwiftUI/AppKit 视图，避免插件数量增长破坏浮层结构。

### R9. Plugin Developer Mode

- 设置中提供默认关闭的开发者模式，开启后可“加载未打包插件”、手动重新载入和打开插件调试器。
- 调试器至少显示 manifest/schema 校验、插件与能力信息、当前配置、内容匹配特征/分数/原因、执行结果 JSON、耗时、运行时错误和本次会话日志。
- 调试器允许开发者输入测试文本分别运行匹配和能力 handler；测试文本与插件日志只存在内存，关闭调试会话即清空，正式运行日志不包含原文或插件输出正文。
- 外置脚本在独立 runner 进程执行。宿主施加执行超时、输入/输出和日志大小上限；超时、崩溃、无效输出或协议版本不兼容只禁用本次执行，不影响主 App。
- 时间工具示例包提供固定测试夹具和可重复的验证脚本，作为插件作者目录、清单、配置和调试协议的参考实现。

### R10. State, Privacy And Accessibility

- 新选区出现、来源应用退出或选区失效时，旧的异步结果不能覆盖新上下文。
- 浮层不能默认抢走来源应用焦点；只有进入搜索输入、能力检索等需要键盘交互的状态时才接管必要焦点。
- 仅使用键盘和仅使用指针，都能完成“选择文字 → 找到能力 → 执行 → 查看结果”的主流程。
- 不记录或持久化原始选中文字；诊断日志只保留错误类型、能力标识和不含正文的运行状态。
- 系统翻译应标识为设备端；AI 或其他远程提供方应在执行前后明确显示提供方，且只在用户确认后发送当前文字。
- 状态表达不能只依赖颜色；关键控件需要明确标签、焦点顺序和辅助功能描述。

## Acceptance Criteria

- [ ] AC1：在已授权且目标应用支持 Accessibility 的情况下，用指针选中文字会在选区附近显示浮层；用键盘选中文字后可通过全局快捷键显示同一浮层。
- [ ] AC2：应用以类似 PopClip 的后台菜单栏工具运行；用户可随时停用和重新启用自动弹出，停用期间不响应新选区。
- [ ] AC3：浮层在屏幕边缘和多显示器环境中保持可见，并尽量不遮挡选区。
- [ ] AC4：`复制` 始终位于首位，复制的是当前选区而非历史内容，并具有成功反馈。
- [ ] AC5：首次安装仅外显 `搜索` 与 `翻译`；固定能力最多 4 项且保持用户排序，推荐变化不影响固定顺序。
- [ ] AC6：推荐行能说明具体能力、所属插件和匹配原因，不重复固定能力，也不会自动执行；无可信候选时整行隐藏。
- [ ] AC7：面对外语文本、URL、代码、地址和普通段落等输入，路由器能依据能力声明给出稳定候选；同一插件的多个能力可独立匹配和排序。
- [ ] AC8：“更多能力”空状态至多显示 5 个匹配项和 3 个最近项；注入大量测试能力后，浮层尺寸和结构保持不变，搜索仍可找到任意能力。
- [ ] AC9：用户能从浮层和菜单栏打开能力中心，完成搜索、固定、取消固定、排序、查看能力详情和编辑插件配置，修改会反映到后续能力执行。
- [ ] AC10：搜索只在用户确认后使用插件当前配置的 Google、Bing 或 DuckDuckGo 打开默认浏览器；翻译只在用户确认后按当前系统/AI 提供方与目标语言运行，并显示提供方、加载、结果或明确错误。
- [ ] AC11：导入独立的 `TimestampTools.clipallplugin` 后，选择 10 位/13 位时间戳时可推荐并执行 `时间戳 → 日期`；选择受支持日期格式时可推荐并执行 `日期 → 时间戳`，两项结果均可复制，并遵守时间工具配置的时区和显示格式。
- [ ] AC12：时间插件面对无效、歧义或越界输入时不输出猜测值，并能展示明确错误；两个能力在同一插件下仍可独立匹配、固定和执行。
- [ ] AC13：拒绝辅助功能权限、目标应用不支持选区属性、翻译语言不可用或异步任务失效时，界面能安全降级且不会运行旧上下文。
- [ ] AC14：键盘和指针两种路径都能完成主流程；关键状态具有文字或图形反馈，不仅依赖颜色。
- [ ] AC15：自动化测试覆盖能力排序、固定能力稳定性、结果上限、设置持久化、时间转换、选区上下文失效和浮层定位边界。
- [ ] AC16：合法 `.clipallplugin` 能经 staging 校验和原子安装进入能力中心；路径穿越、符号链接、重复 ID、未知 schema、超限文件或无效 handler 会被拒绝且不会污染已安装目录。
- [ ] AC17：停用插件后其能力立即退出固定、推荐和搜索结果；重新启用可恢复。卸载后运行文件被删除但源包不受影响，用户可明确选择保留或删除插件配置。
- [ ] AC18：开发者模式能加载未打包的时间工具目录、展示匹配分数与原因、使用测试输入执行两个 handler、查看结构化输出和错误，并能手动重新载入；退出开发模式不会删除源目录。
- [ ] AC19：外置脚本超时、崩溃、返回超限或无效 JSON 时 runner 被终止，主 App 保持可用且错误只归属该插件执行。
- [ ] AC20：时间工具不依赖主 App 内部 Swift 类型即可通过插件验证脚本完成日期/时间戳双向转换、配置格式切换和错误用例。
- [ ] AC21：用户能从菜单栏或系统标准快捷键打开设置窗口，在四个分区完成全局启停、固定能力、插件导入/配置/卸载和开发者模式操作；设置重开后保持一致，且不修改当前选区正文。

## Out Of Scope For Initial Slice

- 插件商店、付费、自动更新、在线目录和开发者发布/签名服务。
- 原生 Swift/Objective-C 动态库、`.bundle` 或任意可执行文件插件；首版外置插件只支持声明式 JavaScript 纯转换运行时。
- 外置插件的网络、文件、剪贴板、辅助功能、自动化、原文替换等宿主权限桥接。
- 云端账户、跨设备同步和云端个性化推荐。
- 基于大模型或远程语义服务的内容路由。
- 搜索、系统翻译和随附时间示例插件之外的能力实现。
- 除 Apple 系统翻译和 OpenAI-compatible AI 适配器之外的具体翻译平台实现。
- Mac App Store 发布、签名、公证、自动更新与生产分发流程。
- 按应用或网站维护排除列表，以及 PopClip 的剪切、粘贴、替换原文、动作复制和 iCloud 同步等进阶能力。

## Constraints And Risks

- 最低系统版本为 macOS 15；首版不兼容更早系统。
- 跨应用取词依赖用户授予辅助功能权限，而且目标应用可能不完整支持 Accessibility 属性；无法承诺所有应用都能返回文字和精确选区坐标。
- Apple 将辅助类应用使用 Accessibility API 列为与 App Sandbox 不兼容的行为；MVP 采用关闭 App Sandbox 的直接分发技术方向。
- App 本身关闭 Sandbox 不代表插件可信；外置脚本仍必须经独立 runner 和零宿主桥接运行，不能继承主进程服务对象。
- 首版插件包允许本地未签名导入，因此安装界面必须展示来源与权限，且不能把“通过格式校验”描述为“安全或可信”。
- 当前开发机只有 Apple Command Line Tools，没有完整 Xcode；进入实现和运行验证前需要安装带 macOS 15 或更新 SDK 的完整 Xcode。
