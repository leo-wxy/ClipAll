# 全局 UI 重设计

## Goal

将 ClipAll 从系统默认式白卡界面升级为统一、有辨识度的原生 macOS
文字工具，同时减少重复的信息架构。用户应能从插件页理解和管理插件提供
的能力，并在选中文字时获得与主界面同源的紧凑浮窗体验。

## Background

- 当前设置页大量使用同构白色卡片、弱对比描边和旧红色强调色，页面层级
  与品牌图标的蓝橙视觉不一致。
- 当前存在独立“能力中心”窗口和菜单入口，但能力由插件提供；单独浏览和
  配置会与插件页形成重复入口。
- 用户已选定并批准浅色、深色视觉基准，要求后续新增 UI 继续遵循同一套
  设计规则。
- 已批准的项目设计规范位于
  `.trellis/spec/frontend/ui-design-system.md`。

## Requirements

### R1. 信息架构收敛

- 删除独立“能力中心”窗口、菜单入口和相关独立导航概念。
- 插件页是能力的归属入口：展示每个插件提供的能力、用途、示例、配置入口
  和固定状态。
- 保留“操作栏”设置，用于查看和调整已固定能力的顺序；它不承担重复的
  能力目录职能。
- 不引入新的 capability repository、view model 或同步层；复用现有插件、
  能力注册表和设置存储。

### R2. 统一设置窗口

- 保留现有主导航：取词、通用、操作栏、插件、开发者。
- 所有页面采用批准的三层信息结构、语义色、排版、列表和状态规则。
- 减少同构卡片与无归属大空白；优先使用分组、行、分隔线和聚焦详情。
- 浅色使用暖象牙底、深墨文字、ClipAll 蓝和极少量橙色星光。
- 深色使用石墨黑、深蓝层级、冷白文字和 ClipAll 蓝高亮。
- 红色只用于错误或破坏性语义，不再作为全局强调色。

### R3. 插件与能力体验

- 插件列表保留内置、开发和本地来源状态。
- 插件详情同时覆盖配置和能力；能力行可表达固定/未固定状态并允许执行
  现有固定操作。
- 插件页搜索可按插件名称、摘要和能力信息过滤，但结果仍以插件为单位；
  能力始终在所属插件详情中展示，不重新创建独立能力目录或窗口。
- 导入、启用、配置、开发引用、调试和卸载行为保持不变。

### R4. 取词浮窗

- 浮窗视觉以批准图中的“操作预览”为目标：横向操作、紧凑材质、细边、
  适量阴影、当前能力蓝色高亮，并适配浅色与深色。
- 蓝色文字选区和两端圆点属于来源 App，不是 ClipAll 绘制范围。
- 更多能力、执行、翻译、结果和错误状态沿同一浮窗材质向下展开。
- 原文和译文是静态标注内容；二者之间不得出现箭头、连接线或过渡效果。
- 现有 324 点宽度、顶边锚定、非激活面板、焦点、关闭和输入保护契约保持
  不变。

### R5. 设计系统与实现约束

- 共享配色、排版、间距、圆角、阴影和状态必须由 `ClipAllTheme` 或现有
  SharedUI 原语集中管理。
- 不新增第三方 UI 或动画依赖；优先 SwiftUI/AppKit 原生能力。
- 不为单一页面创建新的设计抽象、配置开关或未来扩展层。
- Hover、pressed、keyboard focus、selected、disabled 和 accessibility
  状态必须明确区分，不能只依赖颜色。
- 动效即时、克制、可中断；减少动态效果和减少透明度设置必须有降级路径。

### R6. 行为兼容

- 除删除独立能力中心并把能力管理收回插件页外，现有插件生命周期、能力
  执行、固定顺序、设置持久化、取词和剪贴板行为不得改变。
- 不更改插件协议、manifest、Runner、持久化 schema 或外部 API。
- 不修改与本任务无关的现有未提交文件。

## Out Of Scope

- 新增插件能力或改变能力匹配算法。
- 修改插件运行时协议、配置 schema 或安全边界。
- 重新设计 App 图标、菜单栏图标或来源 App 的文字选区。
- 新增主题选择器、自定义主题编辑器或除系统明暗模式外的主题。
- 为概念图中不存在于当前产品的内容处理能力补实现。

## Acceptance Criteria

- [ ] 应用不再声明或展示独立“能力中心”窗口及菜单入口。
- [ ] 代码与当前架构文档不再保留 `CapabilityCenter`、
      `capability-center` 或“能力中心”现行产品概念。
- [ ] 插件页可查看每个插件的能力、用途/示例、配置入口和固定状态。
- [ ] “操作栏”页仍可调整已固定能力顺序，且不重复完整能力目录。
- [ ] 取词、通用、操作栏、插件、开发者页面符合批准设计规范，重要页面
      不再由同构白卡和大面积无归属空白构成。
- [ ] 浅色与深色界面分别与批准视觉基准保持同一配色关系和层级。
- [ ] 浮窗的 ready、更多能力、执行、结果、翻译和错误状态共享同一明暗
      视觉语言，且不改变现有几何与输入行为。
- [ ] 原文与译文展示之间没有箭头、连接线或动效提示。
- [ ] `swift build --target ClipAll` 通过。
- [ ] `Scripts/verify-overlay-state.sh` 通过。
- [ ] 受影响功能的现有 verification 可执行项通过，并补充覆盖能力中心删除
      与插件页能力固定行为的最小回归检查。
- [ ] 使用 `Scripts/install-local-app.sh` 安装并启动
      `/Applications/ClipAll.app`，完成浅色、深色、设置页、插件页和浮窗
      真实 App 截图核对。
- [ ] 用户在真实 App 中明确验收通过前，不提交、不归档、不声称完成。

## Confirmed Decisions

- 使用 Ponytail `full`：删除优于新增，复用原生和现有组件，不新增依赖。
- 能力从属于插件，不单独拿出来。
- 浅色以 `Docs/Images/clipall-ui-design-light.png` 为视觉基准。
- 深色以 `Docs/Images/clipall-ui-design-dark.png` 为视觉基准。
- 浮窗采用基准图中的操作预览风格；来源 App 的选区不属于实现范围。
